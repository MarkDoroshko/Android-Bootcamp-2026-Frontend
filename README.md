# Техническое задание на разработку программного продукта для планирования встреч

## 1. Общие описание
Необходимо разработать программный продукт для планирования встреч сотрудников внутри компании. Система состоит из клиентского мобильного приложения и серверной части.

## 2. Клиентская часть (Android-приложение)
Клиентом является **Android-приложение**, которое должно быть реализовано на **Kotlin** или **Java** с использованием **адаптивной верстки**.

Приложение должно предоставлять интуитивно понятный интерфейс, в котором реализован следующий функционал:

*   **Регистрация и авторизация** сотрудника.
*   **Настройка личного профиля**.
*   **Создание встречи** с возможностью приглашения других сотрудников. Приглашенные сотрудники должны иметь возможность дать бинарный ответ (**принял** / **не принял**).
*   **Просмотр списка активных приглашений** на встречи с возможностью дать ответ о возможности посещения.
*   **Просмотр собственного расписания встреч** в разрезе дня, недели и месяца.

**Важное условие:** временные слоты для встреч разбиты строго по часам. Например, можно создать встречу на 9:00–10:00, но создание встречи на 9:10, 9:05 и т.д. — невозможно.

## 3. Серверная часть
Сервер представляет собой **микросервис на Spring Boot**, работающий с СУБД **PostgreSQL** или **H2**.

Серверное приложение должно:
*   Предоставлять API, необходимый для полноценной работы мобильного приложения.
*   Осуществлять все основные операции с данными в базе через **Spring Data JPA**.
*   Использовать **Liquibase** для создания схемы базы данных и ее предзаполнения.

# User Stories
1. Как сотрудник компании, я хочу зарегистрироваться в системе, чтобы планировать встречи
2. Как зарегистрированный пользователь, я хочу войти в систему, чтобы пользоваться функционалом приложения
3. Как пользователь, я хочу редактировать свой профиль, чтобы другие видели актуальную информацию обо мне
4. Как пользователь, я хочу создать встречу, чтобы встретиться с коллегами
5. Как создатель встречи, я хочу пригласить других пользователей, чтобы они могли ответить на предложение
Как пользователь, я хочу 6. просматривать список приглашений, чтобы отвечать на них
7. Как приглашенный пользователь, я хочу ответить на предложение, чтобы организатор узнал о моем решении
8. Как участник встреч, я хочу видеть свое расписание встреч, чтобы планировать время

# Use Cases:
1. Регистрация пользователя
Цель: Регистрация пользователя для последующего входа
Акторы: Сотрудник
Предусловие: Сотрудник не зарегистрирован
Основной поток:
Пользователь вводит почту, пароль и подтверждение пароля
Приложение отправляет данные на сервер
Сервер проверяет:
уникальность почты
совпадение пароля и подтверждения пароля
соответствие пароля требованиям
и возвращает ответ
Приложение переходит на экран авторизации
Альтернативный поток:
Пользователь с такой почтой уже существует / пароли не совпадают / пароль слишком слабый
Сервер возвращает ошибку
Приложение отображает сообщение об ошибке

Задачи frontend:
Реализовать экран регистрации, разместив на нём поля для ввода email и пароля, а также кнопку для отправки данных на сервер.
Обработка нажатия на кнопку “Регистрация” с последующей валидацией данных.
При успешной валидации отправить POST запрос на сервер, иначе ошибка валидации.
Обработать ответ от сервера. Успех -> Сохранение токена в local storage и редирект на главный экран. Провал -> отображение ошибки. 

2. Авторизация пользователя
Цель: Вход пользователя в систему
Акторы: Сотрудник
Предусловие: Сотрудник зарегистрирован
Основной поток:
Пользователь вводит почту и пароль
Приложение отправляет данные на сервер

Пользователь переходит на главный экран приложения
Альтернативный поток:
Введена неверная почта или пароль
Сервер возвращает ошибку авторизации
Приложение отображает сообщение об ошибке

Задачи frontend:
Реализовать экран авторизации, разместив на нём поля для ввода email и пароля, а также кнопку для отправки данных на сервер.
Обработка нажатия на кнопку “Войти” с последующей валидацией данных.
При успешной валидации отправить POST запрос на сервер, иначе ошибка валидации.
Обработать ответ от сервера. Успех -> Сохранение токена в local storage и редирект на главный экран. Провал -> отображение ошибки. 

3. Редактирование профиля пользователя
Цель: Обновление своих личных данных
Акторы: Сотрудник
Предусловие: Пользователь авторизован
Основной поток:
Пользователь открывает экран профиля
Пользователь изменяет данные профиля
Пользователь нажимает кнопку сохранения
Приложение отправляет обновленные данные на сервер
Сервер обновляет данные пользователя в базе
Сервер возвращает успешный ответ
Приложение обновляет интерфейс
Альтернативный поток:
Данные не прошли валидацию
Сервер возвращает ошибку
Приложение отображает сообщение об ошибке

Задачи frontend:
Реализация экрана редактирования профиля пользователя со всеми полями для редактирования / заполнения данных, а также кнопки для отправки данных на сервер.
При открытии экрана запрашивать актуальные данные пользователя с сервера GET-запросом, используя токен.
Обработка нажатия кнопки “Изменить” с последующей валидацией данных.
При успешной валидации отправить POST запрос на сервер, иначе ошибка валидации.
Обработать ответ от сервера. Успех -> Обновление данных в профиле. Провал -> отображение ошибки.

4. Создание встречи
Цель: Создание новой встречи
Акторы: Сотрудник
Предусловие: Пользователь авторизован
Основной поток:
Пользователь вводит название и описание встречи
Пользователь выбирает дату и время начала и окончания встречи
Пользователь выбирает сотрудников для приглашения?
Приложение отправляет данные встречи на сервер
Сервер выполняет проверки
Сервер сохраняет встречу в базе данных
Сервер создает приглашения для выбранных сотрудников?
Сервер возвращает успешный ответ
Альтернативный поток:
Время указано не по целым часам / конец встречи раньше начала / встреча пересекается с другой
Сервер возвращает ошибку
Приложение отображает сообщение об ошибке

Задачи frontend:
Реализация экрана создания профиля пользователя со всеми полями для заполнения данных, а также кнопки для отправки данных на сервер.
Обработка нажатия кнопки “Создать” с последующей валидацией данных.
При успешной валидации отправить POST запрос на сервер, иначе ошибка валидации.
Обработать ответ от сервера. Успех -> Редирект на главный экран. Провал -> отображение ошибки.

5. Просмотр приглашений на встречи
Цель: Просмотр списка приглашений пользователя
Акторы: Сотрудник
Предусловие: Пользователь авторизован
Основной поток:
Пользователь открывает раздел с приглашениями
Приложение отправляет запрос на сервер
Сервер возвращает список активных приглашений
Приложение отображает список приглашений

Задачи frontend:

При открытии экрана сделать GET-запрос для получения актуальных данных о приглашениях.
Обработать ответ от сервера. Успех -> отображение данных. Провал -> отображение ошибки.

6. Ответ на приглашение
Цель: Принятие или отклонение приглашения на встречу
Акторы: Сотрудник
Предусловие: Пользователь авторизован, приглашение существует
Основной поток:
Пользователь открывает приглашение
Пользователь принимает или отклоняет приглашение на встречу
Приложение отправляет ответ на сервер
Сервер сохраняет статус приглашения
Сервер возвращает успешный ответ
Приложение обновляет статус приглашения

Задачи frontend:
Создание кнопок на item встречи для бинарного ответа пользователя на приглашение.
Обработка нажатия на кнопки с последующим запросом на сервер (POST).
Обработка ответа от сервера. Успех -> скрываем кнопки, обновляем экран активных приглашений. Провал -> показываем ошибку.

Цель: Просмотр личного расписания встреч
Акторы: Сотрудник
Предусловие: Пользователь авторизован
Основной поток:
Пользователь выбирает режим просмотра расписания по дням/неделям/месяцам
Приложение отправляет запрос на сервер
Сервер возвращает расписание пользователя
Приложение отображает расписание

Задачи frontend:
Реализация экрана просмотра приглашений в удобном формате, позволяющий просмотреть встречи на день, неделю и месяц.
При открытии экрана сделать GET-запрос для получения актуальных данных о встречах.
Обработать ответ от сервера. Успех -> отображение данных. Провал -> отображение ошибки.

8. Выход пользователя из системы
Цель: Завершение пользовательской сессии
Акторы: Сотрудник
Предусловие: Пользователь авторизован
Основной поток:
Пользователь нажимает «Выйти»
Приложение удаляет сохранённый токен
Пользователь перенаправляется на экран авторизации

Задачи frontend:
Обработка нажатия кнопки “Выход”.
При нажатии: удаление сохраненного в local storage токена; перенаправление пользователя на экран авторизации.
